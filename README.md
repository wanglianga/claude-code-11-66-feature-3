# 稽核证据台 · 医保结算离线复核工作台

浏览器端离线稽核明细工作台，用来把数百万条已脱敏的医保结算明细、规则命中、按服务日生效的机构资质快照与稽核处理结论，整理成可离线复核的证据材料。

核心口径：**支付金额按结算行唯一计额**。一条结算行命中多条规则时，金额只计一次，每条命中仍作为独立证据解释；资质快照在服务日重叠或空档时一律列为待核，不任选一版；案件冻结后来源批次或结论被更正，只生成标注受影响明细的新材料版本，不改写已封存数据包。

## 技术栈

- React 18 + TypeScript + Vite 6
- IndexedDB（通过 `idb`）保存数据集、已封存材料与处理日志
- Web Worker 负责样例批次生成与全量分析，避免阻塞界面
- `@noble/hashes` 计算 SHA-256，`fflate` 打包 ZIP
- 无后端、无数据库服务；所有数据留在浏览器本地

## 本地启动

```bash
# 安装依赖（换到公司镜像时按需替换 registry）
npm install --registry=https://registry.npmmirror.com

# 开发模式（默认 http://localhost:5173）
npm run dev

# 生产构建 + 本地预览（默认 http://localhost:4173）
npm run build
npm run preview

# 单元测试（金额、资质、材料包、更正差异）
npm test
```

第一次打开会自动在 Web Worker 中生成 720 条确定性样例结算行并写入 IndexedDB，随后进入「工作台总览」。

## Docker 一键启动

```bash
docker compose up -d --build
# 浏览器打开 http://localhost:8080
```

也可以单独构建镜像：

```bash
docker build -t medaudit-evidence-desk:1.0.0 .
docker run --rm -p 8080:80 medaudit-evidence-desk:1.0.0
```

镜像为两阶段构建（Node 22 构建静态资源 → Nginx 托管），容器内不需要任何外部服务。

## 页面与功能

| 页面 | 作用 |
| --- | --- |
| 工作台总览 | 金额口径对照（行口径 vs 按命中摊平）、规则分布、多命中样例、待核线索 |
| 稽核明细 | 逐行核对；点开任意行查看规则命中、资质快照、处理结论与行摘要 |
| 范围冻结 | 按检查项目 / 统筹区 / 机构 / 规则 / 服务日期组合范围，预览并冻结材料 |
| 证据材料 | 材料列表、逐行证据回查、来源清单、校验信息、导出 ZIP / 单文件 HTML |
| 更正差异 | 对比两份材料，列出受影响明细、变更字段与金额差额 |
| 批次目录 | 文件批次、字段字典、规则目录、来源版本，可重建样例 |
| 处理日志 | 导入 / 冻结 / 更正 / 导出 / 校验事件流（只追加），可导出 JSON |
| 验收核对 | 由输入样例实时算出四类验收结论，全部通过后才标记通过 |

### 数据组织方式

材料采用 **“结算行主表 + 证据引用表”**：

- `rows[]`：每行结算明细只出现一次，含 `paymentAmountCents`。
- `evidence.hits[] / qualifications[] / conclusions[]`：共享证据集中存放。
- 行内通过 `hitIds`、`qualificationCandidateIds`、`primaryQualificationId`、`conclusionId` 引用证据。

相比“按案件组织的证据包”，共享证据不会因为多命中被复制，存储更省；代价是审阅人需跟随引用查看依据——界面与离线审阅器都提供了行 → 证据的双向跳读。

默认样例的实际规模（720 行、固定种子）实测：

| 指标 | 数值 |
| --- | --- |
| 结算行 | 720 |
| 支付金额（行口径） | ¥230,547.83 |
| 规则命中 | 183 条（平均 0.25 条/行，覆盖 6 类规则） |
| 多命中行（≥2 条） | 18 行 |
| 按命中摊平会多计的金额 | ¥13,647.64 |
| 资质待核行（重叠/空档） | 44 行（空档 41、重叠 3） |
| 待核 + 待结论 | 242 行（其中资质待核 44 行） |
| 资质快照 / 批次 | 51 份 / 6 个 |

若按“命中摊平后汇总”，同一结算行的金额会被重复计入 ¥13,647.64；本工作台以结算行为唯一计额单位，只计 ¥230,547.83。

### 冻结与更正规则

- 冻结时对范围内的行、证据、字段字典分别计算 SHA-256，写入 `manifest`，并对整份材料计算内容摘要。
- 材料状态固定为「已封存」，只读；更正不会修改已有材料。
- 「处理来源更正」支持两类场景：
  - **处理结论更正**：追加新版本结论（`version + 1`），原结论保留在历史批次。
  - **资质快照补正**：追加补正快照，通过 `supersedes` 声明取代的旧快照，旧快照仍保留可回查。
- 更正后按原材料的范围与版本号派生新材料（`basisPackageId` 指向前一版），并在 `correction.affectedRowIds` 标注受影响明细。
- 资质解析按服务日匹配快照区间：无快照 → 空档；多份并行快照 → 重叠；唯一快照状态非「有效」→ 状态异常。三种都列待核，`primaryQualificationId` 为空。

## 测试账号

本工作台是纯前端离线应用，**没有登录、没有账号体系**。打开即用；「生成人」字段只是材料上的署名文本，可自由填写，不做鉴权。

## 验收方式

页面「验收核对」会基于当前输入样例实时演算下列检查，全部通过才显示 10/10：

1. **金额核对**
   - 输入样例逐行独立累加，与材料行主表合计一致。
   - 材料行主表内部一致（行数、合计）。
   - 多命中行只计一次；剔除的重复计额等于逐行 `(命中数 - 1) × 行金额`。
2. **规则与资质回查**
   - 每条命中含规则编码、条款、发现，引用无悬空。
   - 重叠 / 空档行不指定唯一版本，快照引用完整。
   - 采用的主版本，其有效期覆盖服务日（按历史快照而非当前状态）。
3. **离线打开**
   - 生成的单文件 HTML 无 `<script src>`、无外链，内嵌全部数据与内容摘要。
   - 下载后断网双击即可打开，检索、筛选、行 → 证据跳读、校验信息面板均可用。
4. **更正前后差异**
   - 结论更正只影响指定明细，金额差额为 0，封存材料金额不变。
   - 资质补正只改变资质依据，金额不变，旧快照与旧材料保留。

### 人工复核路径（推荐用于演示）

1. 打开「稽核明细」，查看 `S-000001`：命中 `R-101 + R-201 + R-401` 三条，支付金额只计一次，资质显示「资质重叠」，候选两份快照、无主版本；按命中摊平会得到更高的虚假金额，行摘要旁的提示会说明不可相加。
2. 查看 `S-000002`：「资质空档」，无候选快照，复核状态为待核；再查 `S-000003`：「资质注销」状态异常，同属待核。
3. 打开「范围冻结」，选择「全部待核行」快捷范围，冻结为材料。
4. 在「证据材料」点「导出 ZIP」，解压后双击 `index.html`，断网也能逐行核对。
5. 点「处理来源更正」→「资质快照补正」→「生成更正后新材料」，得到 V2 材料；原材料与金额不变。
6. 打开「更正差异」，基准选 V1、比较选 V2，可见仅受影响行的「资质依据」变化，金额差额 ¥0.00。
7. 打开「验收核对」确认 10/10 通过。

也可以在「批次目录」调整行数、随机种子、异常率后重建样例，验收页会基于新样例重新演算。

## 目录结构

```
src/
  core/       样例生成、分析口径、材料构建与校验、更正、离线审阅器、导出
  db/         IndexedDB 封装（数据集 / 材料 / 事件 / 批次）

  components/ 通用组件（徽标、抽屉、弹窗、页头、卡片、侧栏）

docker-compose.yml
```

## 构建与容器说明

- 生产构建产物为纯静态文件，`public/sw.js` 只在生产模式注册，提供应用壳缓存；材料包本身完全不依赖 service worker。
- Nginx 配置对静态资源设置长缓存，对 SPA 路由回退到 `index.html`。
- 本次交付未在容器内实际执行 `docker build`（当前环境无 Docker 守护进程），Dockerfile 与 compose 已按常规两阶段构建编写；本地 `npm run build` 与 `npm run preview` 已实际执行。

## 已知边界

- 样例数据在浏览器内确定性生成（固定种子），用于演示口径与验收；未接入真实结算文件导入。真实接入时替换 `core/sample.ts` 的生成器并保持行/证据结构即可。
- 更正场景为内置演示场景（3 条结论、2 条资质补正），用于稳定复现更正前后差异。
- 单位统一为「分」，全部金额运算使用整数，避免浮点误差。
