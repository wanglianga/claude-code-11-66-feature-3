# 稽核证据台 · 医保结算离线复核工作台

浏览器端离线稽核明细工作台，用来把数百万条已脱敏的医保结算明细、规则命中、按服务日生效的机构资质快照与稽核处理结论，整理成可离线复核的证据材料。

核心口径：**支付金额按结算行唯一计额**。一条结算行命中多条规则时，金额只计一次，每条命中仍作为独立证据解释；资质快照在服务日重叠或空档时一律列为待核，不任选一版；案件冻结后来源批次或结论被更正，只生成标注受影响明细的新材料版本，不改写已封存数据包。

本次迭代新增 **「医保服务项目代码沿革与历史可比统计」** 模块（政策统计）：读取跨年度结算提取行的服务日期与项目编码，结合版本化目录与映射关系，输出原始代码口径与两种可比类别口径，供政策人员研判跨期变化。核心规则：**每行金额只落入一个归属**（唯一类别 / 歧义池 / 未映射池），一对多拆分候选不当作已分配金额；代码复用按服务发生日分段释义，不用现行释义回填历史；目录更正只重建涉及代码和期间的新统计版本，旧口径封存可复现。

## 技术栈

- React 18 + TypeScript + Vite 6
- IndexedDB（通过 `idb`）保存数据集、已封存材料与处理日志
- Web Worker 负责样例批次生成与全量分析，避免阻塞界面
- `@noble/hashes` 计算 SHA-256，`fflate` 打包 ZIP
- 无后端、无数据库服务；所有数据留在浏览器本地

## 本地启动

```bash
# 安装依赖（换到公司镜像时按需替换 registry）
npm install --registry=https://registry.npmmirror.com

# 开发模式（默认 http://localhost:5173）
npm run dev

# 生产构建 + 本地预览（默认 http://localhost:4173）
npm run build
npm run preview

# 单元测试（金额、资质、材料包、更正差异）
npm test
```

第一次打开会自动在 Web Worker 中生成 720 条确定性样例结算行并写入 IndexedDB，随后进入「工作台总览」。

### 数据组织方式

材料采用 **“结算行主表 + 证据引用表”**：

- `rows[]`：每行结算明细只出现一次，含 `paymentAmountCents`。
- `evidence.hits[] / qualifications[] / conclusions[]`：共享证据集中存放。
- 行内通过 `hitIds`、`qualificationCandidateIds`、`primaryQualificationId`、`conclusionId` 引用证据。

相比“按案件组织的证据包”，共享证据不会因为多命中被复制，存储更省；代价是审阅人需跟随引用查看依据——界面与离线审阅器都提供了行 → 证据的双向跳读。

默认样例的实际规模（720 行、固定种子）实测：

| 指标 | 数值 |
| --- | --- |
| 结算行 | 720 |
| 支付金额（行口径） | ¥230,547.83 |
| 规则命中 | 183 条（平均 0.25 条/行，覆盖 6 类规则） |
| 多命中行（≥2 条） | 18 行 |
| 按命中摊平会多计的金额 | ¥13,647.64 |
| 资质待核行（重叠/空档） | 44 行（空档 41、重叠 3） |
| 待核 + 待结论 | 242 行（其中资质待核 44 行） |
| 资质快照 / 批次 | 51 份 / 6 个 |

若按“命中摊平后汇总”，同一结算行的金额会被重复计入 ¥13,647.64；本工作台以结算行为唯一计额单位，只计 ¥230,547.83。

### 冻结与更正规则

- 冻结时对范围内的行、证据、字段字典分别计算 SHA-256，写入 `manifest`，并对整份材料计算内容摘要。
- 材料状态固定为「已封存」，只读；更正不会修改已有材料。
- 「处理来源更正」支持两类场景：
  - **处理结论更正**：追加新版本结论（`version + 1`），原结论保留在历史批次。
  - **资质快照补正**：追加补正快照，通过 `supersedes` 声明取代的旧快照，旧快照仍保留可回查。
- 更正后按原材料的范围与版本号派生新材料（`basisPackageId` 指向前一版），并在 `correction.affectedRowIds` 标注受影响明细。
- 资质解析按服务日匹配快照区间：无快照 → 空档；多份并行快照 → 重叠；唯一快照状态非「有效」→ 状态异常。三种都列待核，`primaryQualificationId` 为空。

## 代码沿革与历史可比统计（政策统计模块）

医保政策团队比较不同年度的结算项目数量和金额时，地方服务代码可能改名、停用、拆分或合并；直接按代码统计会把目录调整误当成就医结构变化，把旧代码金额复制到每个新代码又会重复计算。本模块读取结算提取行的**服务日期**与**项目编码**，按下列口径输出可比统计。

### 数据组织

- **目录（3 版）**：`CAT-2023 / CAT-2024 / CAT-2025（现行）`。每条目录条目保存地方代码、国家项目类别、释义与适用区间；同一代码在不同有效期被重新赋义时（代码复用），各段各有一条条目。
- **国家项目类别**：三级稳定主干（如 `10 检查检验 / 1001 影像检查 / 100103 磁共振检查`），跨目录版本不变，是两种可比口径的共同锚点。
- **映射关系（6 条）**：记录更名、等价替换、拆分、合并及证据来源；证据缺失的映射不参与金额分配；拆分的分摊权重仅作候选参考。
- **结算提取行**：2023-01 至 2025-06 共 431 行（固定种子确定性生成），每行含服务日期、地方代码与基金支付金额（分）。

### 样例覆盖的沿革形态

| 形态 | 样例 | 处理口径 |
| --- | --- | --- |
| 更名 | CS100 彩超规范名称（MAP-01） | 代码连续，映射链留痕 |
| 等价替换 | MR550 → MR551（MAP-02） | 一对一唯一结转 |
| 一对多拆分（有依据） | ZL700 → ZL701/702/703，权重 0.5/0.3/0.2（MAP-03） | 候选 + 分摊依据进歧义池，不计入类别合计 |
| 一对多拆分（无依据） | ZH600 → ZH601/ZH602（MAP-04） | 无分摊依据，全额留歧义池，不复制给多个新类 |
| 合并 | XL101 + XL102 → XL100（MAP-05） | 多对一唯一结转 |
| 代码复用 | A100：2023「红外线治疗」→ 2025「中医定向透药治疗」 | 按服务发生日分段，不回填；2023 年旧项停用无后继 |
| 无依据映射 | QT500 → QT501 证据缺失（MAP-06） | 证据补齐前不参与分配，列入无法唯一映射 |
| 停用无后继 / 目录外 | XT500 调出目录；TP999 从未收录 | 未映射池单列原因 |

### 两种可比口径与覆盖率

统计运行按服务日期选用对应目录，输出：

1. **原始代码口径**：按结算时代码原样汇总，展示代码 churn（会误读目录调整）。
2. **最细类别投影**：历史明细沿映射链投影到现行目录最细国家类别。一对多拆分一律进**歧义池**并保留候选与分摊依据（参考分摊不计入任何类别合计）；无法唯一映射的金额单列。
3. **上级类别汇总**：回退到新旧目录共同稳定的二级类别，不经映射、计算简单、趋势更稳，但会掩盖子项目之间的真实结构迁移（如 ZL700 拆分在「2002 康复治疗」层级完全隐形）。

**映射覆盖率的分母 = 纳入统计的全部结算提取行**（金额与行数两个维度），分子 = 唯一映射部分；歧义池与未映射池不计入分子，并始终同时显示未映射范围。金额守恒恒等式：唯一映射 + 歧义池 + 未映射池 ≡ 原始口径总计（页面与验收均实时校验）。

| --- | --- | --- | --- | --- | --- | --- |
| 2023 | 188 | ¥33,501.90 | ¥22,840.36（68.2%） | ¥5,440.59 | ¥5,220.95 | ¥33,408.84（99.7%） |
| 2024 | 147 | ¥29,279.13 | ¥19,301.29（65.9%） | ¥5,785.41 | ¥4,192.43 | ¥29,186.79（99.7%） |

### 统计版本与目录更正

- 每次统计运行冻结**输入快照**（目录条目 + 映射）与**输出摘要**（行级解析结果的 SHA-256），旧版本随时可用冻结输入复现（「统计版本」页实时校验）。
- 目录更正批次 `B-CAT-C1` 演示两类更正：补录 MAP-06 对照证据（QT500→QT501 转为可分配）、XL100 国家类别 100302→100301 修正。
- 重建遵循「只重建涉及代码和期间」：V2 实际重算 98 行（QT500/QT501/XL100/XL101/XL102，2023–2025），其余 333 行逐字沿用 V1；版本差异页展示最细类别金额差（心电检查 +¥4,761.03 = 脑电与脑功能 −¥4,761.03；电疗与磁疗 2023/2024 合计 +¥7,210.27），上级汇总口径不受本次更正影响。
- 更正后最细口径金额覆盖率提升：2023 年 68.2% → 79.2%，2024 年 65.9% → 77.9%。

## 验收方式

页面「验收核对」会基于当前输入样例实时演算下列检查。稽核模块 10 项：

1. **金额核对**
   - 输入样例逐行独立累加，与材料行主表合计一致。
   - 材料行主表内部一致（行数、合计）。
   - 多命中行只计一次；剔除的重复计额等于逐行 `(命中数 - 1) × 行金额`。
2. **规则与资质回查**
   - 每条命中含规则编码、条款、发现，引用无悬空。
   - 重叠 / 空档行不指定唯一版本，快照引用完整。
   - 采用的主版本，其有效期覆盖服务日（按历史快照而非当前状态）。
3. **离线打开**
   - 生成的单文件 HTML 无 `<script src>`、无外链，内嵌全部数据与内容摘要。
   - 下载后断网双击即可打开，检索、筛选、行 → 证据跳读、校验信息面板均可用。
4. **更正前后差异**
   - 结论更正只影响指定明细，金额差额为 0，封存材料金额不变。
   - 资质补正只改变资质依据，金额不变，旧快照与旧材料保留。

统计模块（代码沿革与可比统计）8 项：

1. **金额守恒**：最细口径与上级口径下，唯一映射 + 歧义池 + 未映射池均恒等于原始口径总计，每行金额只落入一个归属。
2. **拆分候选不当作已分配**：歧义池金额不进入任何类别合计，候选均带分摊依据标注。
3. **代码复用按服务日分段**：A100 在 2023 年归入物理治疗、2025 年归入中医治疗，不用现行释义回填。
4. **拆分无依据不复制金额**：ZH600 / ZL700 全部进歧义池；ZH600 候选无权重，ZL700 候选带权重。
5. **覆盖率分母明确**：逐年校验 唯一映射 + 歧义池 + 未映射池 = 全部提取行（行数与金额）。
6. **映射依据可回查**：映射结转行的每一跳均有证据齐全的映射记录；歧义 / 未映射行均有原因。
7. **目录更正只重建涉及范围**：V1→V2 实际变化行 ⊆ 声明涉及代码（QT500/QT501/XL100/XL101/XL102），其余逐字沿用（未执行更正时该项按通过计并注明）。
8. **旧口径可复现**：每个统计版本用冻结输入重算，输出摘要一致。

### 人工复核路径（推荐用于演示）

稽核模块：

1. 打开「稽核明细」，查看 `S-000001`：命中 `R-101 + R-201 + R-401` 三条，支付金额只计一次，资质显示「资质重叠」，候选两份快照、无主版本；按命中摊平会得到更高的虚假金额，行摘要旁的提示会说明不可相加。
2. 查看 `S-000002`：「资质空档」，无候选快照，复核状态为待核；再查 `S-000003`：「资质注销」状态异常，同属待核。
3. 打开「范围冻结」，选择「全部待核行」快捷范围，冻结为材料。
4. 在「证据材料」点「导出 ZIP」，解压后双击 `index.html`，断网也能逐行核对。
5. 点「处理来源更正」→「资质快照补正」→「生成更正后新材料」，得到 V2 材料；原材料与金额不变。
6. 打开「更正差异」，基准选 V1、比较选 V2，可见仅受影响行的「资质依据」变化，金额差额 ¥0.00。
7. 打开「验收核对」确认稽核 10/10 通过。

统计模块（代码沿革与可比统计）：

1. 打开「目录沿革」，在代码时间线中确认 `A100` 的分段释义：2023 年「红外线治疗」（光疗与热疗）、2024 年停用、2025 年「中医定向透药治疗」（中医外治）。
2. 打开「映射关系」，对照六类沿革样例与 MAP-06「证据缺失 · 不参与分配」标记。
3. 打开「可比统计」，默认最细类别投影：查看覆盖率（2023 年 68.2%）、歧义池（ZL700/ZH600 候选与分摊依据）、未映射原因分组；点击「100103 磁共振检查」2024 年单元格，在抽屉中沿 `MR550 → MAP-02 → MR551` 回查证据文件。
4. 切换「上级类别汇总」：ZL700 拆分在「2002 康复治疗」层级隐形，覆盖率升至 99.7%，体会「趋势更稳但掩盖子项目迁移」。
5. 切换「原始代码口径」：MR550 在 2025 年「消失」、MR551「新设」——目录调整被误读为结构变化的反例。
6. 打开「统计版本」，点「应用目录更正 B-CAT-C1」：生成 V2，差异区可见仅 QT500/QT501/XL100/XL101/XL102 的 98 行重算、333 行逐字沿用；每行版本均有「可复现」标记。
7. 回到「可比统计」在 V1 / V2 页签间切换，观察「200102 电疗与磁疗」2023–2024 年金额与覆盖率变化（旧口径仍可查看）。
8. 打开「验收核对」确认统计 8/8 通过。

也可以在「批次目录」调整行数、随机种子、异常率后重建样例，验收页会基于新样例重新演算（重建稽核样例会同时把统计模块恢复为基线样例）。

```
docker-compose.yml
```

## 构建与容器说明

- 生产构建产物为纯静态文件，`public/sw.js` 只在生产模式注册，提供应用壳缓存；材料包本身完全不依赖 service worker。
- Nginx 配置对静态资源设置长缓存，对 SPA 路由回退到 `index.html`。
- 本次交付未在容器内实际执行 `docker build`（当前环境无 Docker 守护进程），Dockerfile 与 compose 已按常规两阶段构建编写；本地 `npm run build` 与 `npm run preview` 已实际执行。

## 已知边界

- 样例数据在浏览器内确定性生成（固定种子），用于演示口径与验收；未接入真实结算文件导入。真实接入时替换 `core/sample.ts` 的生成器并保持行/证据结构即可。
- 统计模块的目录、映射与结算提取同为内置样例（`core/catalog.ts`，2023–2025 年 431 行）；目录版本链为线性（每年一版），映射仅连接相邻版本，未处理一版多年内的中期调整。
- 更正场景为内置演示场景（稽核：3 条结论、2 条资质补正；统计：B-CAT-C1 补证据 + 类别修正），用于稳定复现更正前后差异。
- 拆分的分摊权重只作候选参考，模块不提供「审核后正式分摊」的写回操作；政策人员研判后需在目录管理中另行登记。
- 重建稽核样例（批次目录页）或重置工作区会同时把统计模块恢复为基线样例，已应用的目录更正需重新执行。
- 单位统一为「分」，全部金额运算使用整数，避免浮点误差。
